# ADR-001: MCU нижнього рівня — STM32 Blackpill і власний протокол

> **Статус:** прийнято
> **Дата:** 2026-10-09
> **Автор рішення:** Данило Степанов
> **Пов'язані документи:** `docs/trz.md` (FR-1, FR-4, FR-20), `docs/decisions/ADR-002-navigation-algorithm.md`, `docs/decisions/ADR-003-odometry.md`

## 1. Контекст

Навігацію виконує Raspberry Pi 4 (Linux, ROS 2, SLAM). Linux не гарантує часу реакції, а рухом, енкодерами й аналоговими вимірами треба керувати детерміновано. Потрібен нижній рівень, який працює незалежно від Pi.

## 2. Розглянуті варіанти

| Варіант | Плюси | Мінуси | Висновок |
|---|---|---|---|
| Pi без MCU | Менше плат | Джиттер Linux; немає апаратних лічильників енкодерів і АЦП; безпека залежить від ОС | Відхилено |
| **Pi + STM32F401 (Blackpill)** | Апаратні квадратурні таймери; стабільний АЦП; USB-зв'язок з Pi; є в наявності | Немає радіо (воно нам не потрібне) | **Обрано** |
| Pi + ESP32 | Є в наявності; PCNT для енкодерів | Нелінійний АЦП; радіо без користі (Wi-Fi живе на Pi) | Запасний |

Протокол зв'язку: **власний бінарний** обрано замість micro-ROS. Причини: 64 КБ RAM у F401, прив'язка micro-ROS до версії ROS (ще не обрана), легше налагоджувати, прошивка не залежить від ROS.

## 3. Рішення

- Pi задає бажані швидкості (лінійну й кутову); MCU тримає PID коліс, читає енкодери, ШІМ моторів, щітки й вакуума, аналогові виміри (струм, батарея) і відповідає за аварійну зупинку.
- MCU: STM32F401CCU6 (Blackpill).
- Зв'язок: власні кадри з CRC по USB-CDC або UART; на Pi нода serial-міст публікує стандартні ROS-повідомлення.

## 4. Наслідки

- Безпека не залежить від Pi: бампер зупиняє мотори на MCU, а при відсутності команд 200–500 мс спрацьовує watchdog.
- Обов'язкові елементи протоколу: CRC, номер кадру, часова мітка в одометрії, heartbeat.
- Прошивка не знає про ROS, тож майбутній застосунок чи інший «мозок» можуть підключитись без переробки нижнього рівня.
- micro-ROS можна розглянути пізніше, якщо з'явиться потреба.
- ESP32 devkit лишається під рукою для експериментів.
